# Toadi eyes animation plug-in

A loadable `VisionAlgoPlugin` for the Toadi / EEVE robot that draws eye-panel
animations through the app's **EyesUI** layer API and triggers them over a
small REST listener on **:8081**. It is the runnable companion to
`../../docs/102-eyes-animation-plugin.md`.

This is the dedicated animation plug-in source set: it builds
`libEyesAnimationPlugin.so` and **only** does eye animations. It contributes
no vision algorithms, registers no broker services, and does not touch the
motors.

## What it does

- `createVisionAlgoPlugin(Broker&)` is exported through the Boost.DLL alias
  variable the real `libPlugins.so` looks for.
- With `TOADI_EXAMPLE_HEARTS=1` (set by the deployed wrapper) the factory
  starts the eyes animation controller, which resolves the app's `eyesui`
  broker service, adds an `EyesUILayer` at z-order 2000, and serves eight
  animations on `:8081`: `hearts`, `spidey`, `spidey2`, `spider`, `pumpkin`,
  `badge`, `walle` and procedural `fireworks` (`screen=left|right|both`).
  Overrides: `TOADI_EXAMPLE_HEARTS_PORT`, `TOADI_EXAMPLE_HEARTS_PRIORITY`.
- Without the variable the library loads inertly — the safe default while it
  is merely dropped into `/home/toadi/plugins`.
- `makeVisionAlgos()` returns an empty list, so the stock SLAM plug-in and
  detection framework are untouched.

## Build

```bash
make                       # -> build/libEyesAnimationPlugin.so
make clean
```

Requires the Debian bullseye aarch64 cross sysroot used by this workspace
(`tools/cross-bullseye/root`), or any aarch64 GCC 10/11 toolchain with the
robot's C++11 ABI (`_GLIBCXX_USE_CXX11_ABI=1`, the default). The link line
must keep `-Wl,-z,nodelete`: a VisionAlgo-only library is unloaded after its
factory returns otherwise (spec 100 §7.3). The output depends only on
`libstdc++.so.6`, `libgcc_s.so.1` and `libc.so.6`.

The complete build description — every source file needed and how the shipped
binary was produced — is in `../../BUILD.md`.

## Install on the robot

The persistent, crash-loop-safe deployment is
[`../../setup.sh`](../../setup.sh) — see [`../../SETUP.md`](../../SETUP.md).
A plain copy also works for a quick try:

```bash
scp build/libEyesAnimationPlugin.so root@<robot>:/home/toadi/plugins/
ssh root@<robot> /etc/init.d/toadi restart
```

Look for the plug-in lines in the app log:

```
loading plugins in directory /home/toadi/plugins
found plugin /home/toadi/plugins/libEyesAnimationPlugin.so
Loading plugin /home/toadi/plugins/libEyesAnimationPlugin.so loaded
[eyes-animation-plugin] factory invoked ...
```

## Files

```
Makefile                             build driver (cross aarch64, -z,nodelete)
include/toadi/unknown.h              toadi::Unknown — the registry root object
include/toadi/query_interface.h      QueryInterface<Unknown> — value returned by Broker::queryInterface
include/toadi/broker.h               Broker + makeBroker()
include/toadi/vision_algo_plugin.h   VisionAlgoPlugin, factory declaration, DetectionProcess notes
include/toadi/eyes_ui.h              reconstructed EyesUI / EyesUILayer ABI (dlsym-resolved)
include/toadi/example_hearts.h       controller start + toadi_example_hearts_set_eyesui() test hook
src/animation_plugin.cpp             the plug-in factory (Boost.DLL alias, hearts gate)
src/hearts_controller.cpp            eyes controller: animation table, worker, REST listener
src/hearts.h                         embedded heart frames (128×64, 1 bpp, MSB-first)
src/spidey_frames.h                  filled Spidey lenses (left/right)
src/spidey2_frames.h                 contour Spidey lenses (mirrored left mask)
src/spider_frames.h                  procedural crawling spider
src/pumpkin_frames.h                 pulsing pumpkin
src/badge_frames.h                   pulsing Paw Patrol badge
src/walle_frames.h                   Wall-E eyes (left/right)
```

The six `*_frames.h` headers are generated by
`../../tools/generate_animation_frames.py` from `../../reference/spidey_ref/`;
`hearts.h` embeds `../../hearts/*.bin`.

## Test without the robot

The hearts harness in `../plugin_harness/` loads the built plug-in directly,
injects a fake `eyesui` through `toadi_example_hearts_set_eyesui()`, and
checks the draw calls, layer lifecycle, frame bit order and every REST route:

```bash
make -C ../plugin_harness hearts-run BUILD=/path/to/local/build
```

Expected result: `ALL PASS (0 failures)` — see spec 102 §6.
